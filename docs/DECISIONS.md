- Exclude `casual`, `registered`: they sum to `cnt` exactly. Leaky model R^2 1.000 -> honest ridge 0.583.
- Exclude `cnt_2d_bfr`: a shipped 2-day lag we cannot test the alignment of. Build our own lags instead.
- Exclude `instant`, `yr`, `days_since_2011`: time indexes let a tree predict a flat constant past 2011 and a linear model extrapolate a trend we have no grounds for.
- Split 2011 / H1 2012 / H2 2012 by date. Test set touched once, after all feature work.
- Report mean and persistence baselines with every score. Persistence (test R^2 0.510, MAE 840) is within 0.07 R^2 of ridge and beats it on MAE; that caveat goes in the report.

- 2026-11-24 (Exercise 4 plan, written before running): Hypothesis: HGB fails on 2012 because trees cannot extrapolate past the 2011 demand level. Predicting the daily change `cnt - cnt_lag_1` and adding it back to `cnt_lag_1` might let it follow the growth trend. One experiment, validation only: `python -m src.train --validation-target-experiment` fits a clone of `MODELS["hgb"]` (unchanged parameters, same 15 features, same temporal split) on `train[cnt] - train[cnt_lag_1]`, and reconstructs `valid[cnt_lag_1] + predicted_change`. Today's true count is used only for scoring. It compares baseline_mean, baseline_persistence, ridge, ordinary hgb and hgb-daily-change on the same validation rows (R^2 and MAE in rides) and writes `reports/target_transform_validation.json`. No test rows are fitted, predicted or scored; no tuning and no other transformations; `make all` and `reports/metrics.json` stay untransformed.
- 2026-11-24 (Exercise 4 result, validation only, one run): Validation R^2 / MAE on the same 182 rows: baseline_mean -0.9318 / 2002.2; persistence 0.4507 / 900.6; ridge 0.7224 / 700.4; hgb 0.0977 / 1381.6; hgb_daily_change 0.5642 / 885.8. Predicting the change rescues hgb (+0.4665 R^2, MAE -495.8). It beats persistence on R^2 (+0.1135), but on MAE only by 14.8 rides/day (1.6%), which is likely inside the noise of one 182-day split. It stays well behind ridge (-0.1582 R^2, +185.4 MAE). It is defensible for one-day-ahead forecasts where yesterday's final count is known before predicting today. It is a structural choice (differencing removes the level that trees cannot extrapolate) fixed before the run, not tuned. It would not carry over to multi-day horizons without recursive forecasting. No test rows used; test touched at most once, at the end, and reported as such. Default `make train` reproduced `reports/metrics.json` byte for byte; both metrics files unchanged.
